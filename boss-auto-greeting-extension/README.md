# BOSS Auto Greeting Chrome Extension

这是一个 Manifest V3 Chrome 扩展，用于在 BOSS 直聘职位列表页手动启动、限速执行“打招呼”，并支持按**岗位描述关键词**和**最低薪资**过滤职位。

## 安装

1. 打开 Chrome，进入 `chrome://extensions/`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展”。
4. 选择本目录：`boss-auto-greeting-extension`。

修改代码后记得在扩展管理页点“重新加载”，并刷新职位页面。

## 使用

1. 打开职位页，例如 `https://www.zhipin.com/web/geek/jobs?query=Java&city=101280100`。
2. 点击 Chrome 工具栏里的 `BOSS Auto Greeting`。
3. 设置每日上限、间隔、打招呼内容，以及下方的过滤词和最低薪资。
4. 点击“开始”。需要暂停时点击“停止”。

## 岗位描述过滤

弹窗里的“岗位描述过滤”区块支持以下配置：

| 配置 | 说明 |
| --- | --- |
| 排除词 | 岗位描述命中任意一个词就跳过该职位，不会点击“立即沟通” |
| 必需词 | 留空则不限制；填写后，描述里必须出现这些词才会打招呼 |
| 必需词需全部出现 | 默认命中任一即可；勾选后要求全部必需词都出现 |
| 同时匹配职位标题、公司名 | 默认开启，把左侧列表卡片的文本也纳入匹配范围 |
| 区分英文大小写 | 默认关闭，即 `Java` 与 `java` 等价 |

**分隔方式**：换行、逗号（`,` `，`）、分号（`;` `；`）、顿号（`、`）、竖线（`|`）均可，会自动去空、去重。

```
外包, 驻场
销售
单休
```

**判定顺序**：先排除词，再必需词；命中排除词优先级更高。例如同时包含 `外包` 和 `Java`，仍会被跳过。

**过滤时机**：点击职位卡片 → 等详情面板的“职位描述”渲染完成 → 判定 → 命中则跳过，否则才继续“立即沟通”。描述读不到时**不会拦截**（避免误杀），此时按原逻辑打招呼。

**结果反馈**：

- 弹窗显示“本轮已过滤”计数和当前状态（含命中的词）。
- “最近过滤”列表保存最近 30 条记录（展示前 12 条），含职位标题与命中原因，方便回头调整关键词。
- 每次点“开始”自动清空记录；也可用“清空”按钮手动清空。

**调试**：在职位页控制台执行：

```js
// 验证一段文本会不会被过滤
__bossFilter.evaluate({ excludeKeywords: "外包" }, "这是一段岗位描述……")
// => { pass: false, rule: "exclude", keyword: "外包", reason: "命中排除词「外包」" }

// 查看当前实际抓到的描述文本
__bossFilter.jobDescriptionText()

// 薪资解析与判定
__bossFilter.parseSalary("20-40K·13薪")            // => { min: 20, max: 40, raw: "20-40K·13薪" }
__bossFilter.checkSalary("15-25K", { minSalary: 20 })
// => { pass: false, rule: "salary", keyword: "15-25K", reason: "薪资 15-25K 低于 20K（按下限判断）" }
__bossFilter.readDetailSalary()                    // 查看当前详情页读到的薪资
```

若 `jobDescriptionText()` 返回空，说明 BOSS 直聘页面结构变了，需要调整 `content.js` 里的 `JD_SELECTORS`。

> 注意：关键词是**纯子串匹配**，描述里写“本公司不外包”也会命中“外包”，建议填更具体的词。运行途中修改过滤词不会立即生效，下一次点“开始”才应用。

## 最低薪资过滤

BOSS 直聘自带的薪资筛选经常不生效，插件直接在本地读取职位卡片上的薪资文本做兜底过滤。

| 配置 | 说明 |
| --- | --- |
| 最低月薪（K） | 填 `0` 为关闭；例如填 `20` 表示只接受 20K 以上的职位 |
| 判定依据 | **按下限**（默认）：薪资区间起点低于设定值就跳过；**按上限**：区间终点低于设定值才跳过 |
| 薪资面议 / 无法识别时也跳过 | 默认关闭（放行，避免误杀）；勾上后“面议”和读不出薪资的职位一律跳过 |

举例：设 `20K`，`15-25K` 在「按下限」时会被跳过、在「按上限」时保留；`25-40K` 两种模式都保留。

**支持写法**：`15-25K`、`20-40K·13薪`、`10~20k`、`15K以上`、`1.5-2.5万/月`、`300-500元/天` 等；`·13薪` 这类年终奖后缀会被忽略，只按基础月薪判断。日薪按每月 21.75 个工作日、时薪按每天 8 小时折算成月薪（估算值）。单位无法判断的文本（如 `3-5年`、`面议`）视为「无法识别」。

**过滤时机**：优先读列表卡片上的薪资元素，低薪职位**连详情都不用点开**就被跳过；卡片读不到时，点开职位后再从详情面板补读一次。之后才轮到岗位描述过滤和「立即沟通」。两类过滤共用“本轮已过滤”计数和“最近过滤”记录，记录里会写明具体薪资和判定依据。

**调试**：用 `__bossFilter.readCardSalary(card)` 查看某张卡片读到的薪资；若普遍读不到，说明页面结构变了，需要调整 `content.js` 里的 `SALARY_SELECTORS`。

> 薪资是纯文本解析，属于估算；BOSS 页面把薪资写成图片、或用完全陌生的格式时会读不到，此时按上面的「未知薪资」策略处理。

## 行为说明

- 插件只在你点击“开始”后执行。
- 默认只处理当前已经加载出来的职位。
- 遇到登录、验证码、安全验证、账号异常、访问过于频繁等页面会停止。
- 不读取 cookies、密码、简历文件或浏览器账号数据。
- 页面结构变化时，可能需要调整 `content.js` 里的按钮匹配规则（`JD_SELECTORS` 对应岗位描述，`SALARY_SELECTORS` 对应薪资）。

## 开发

```bash
node tests/filter-rules.test.mjs   # 过滤规则单测，零依赖，不需要 Chrome
```

测试用最小 DOM 桩直接加载 `content.js`，覆盖分隔符解析、排除词、必需词（任一/全部）、大小写、优先级、描述缺失，以及薪资格式解析、单位折算、上下限判定、未知薪资策略等场景。
